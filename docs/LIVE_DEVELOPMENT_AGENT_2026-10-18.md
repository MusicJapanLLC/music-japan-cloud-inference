# 実モデル接続済み開発エージェント

## 今回の成果と対象

既存の FrontierRuntime に実際のコード修正を依頼し、公開クラウドの隔離 Docker でテストし、結果を元の PC に返す開発ループ

```text
登録済みの公開コード課題
  → 修正前のテストをクラウド実行
  → 既存の公開専用 FrontierRuntime へ生成要求
  → JSON の対象ファイルだけを受け入れる
  → 別のクラウド実行で候補をテスト
  → 失敗時は前の候補コードと診断を付けて再生成
  → 成功時も新しいコピーとクラウド実行で再検証
  → 実行記録と採用コードを保存
```

この自動ループの実装と、新しい基盤モデルを学習することは別
今回は重みの学習・専用 GPU の契約や増設・閉じた商用モデルとの同等性試験は実施していない

## 既存環境をそのまま使う

- モデル呼び出しは既存 `FrontierRuntime/frontier_client.py` を再利用
- 応答の申告モデルは `qwen3.8-27b-public` と照合
- 実際の生成先は既存ゲートウェイが使う第三者の公開 Qwen 経路
- PC 内の着信認証トークンは既存クライアントだけが扱い、GitHub やプロンプトへ転送しない
- `allow_paid_api=false` / `allow_subscription_quota=false` は変更しない
- 生成コードは個人 PC で実行しない
- Dots が修正中の FP8 Space、本番 API、会社 DB、他の AI の作業ファイルは変更しない

## 実行手順

現在のクラウド実行は、コードとテストがすでに公開されている `sliding-window-retry-budget` 課題だけを登録している
任意の会社リポジトリを公開扱いに変えて送信する機能ではない

クリーンなこのリポジトリの作業コピーで、既存の git 認証が使える PC から実行する

```powershell
git clone --config core.autocrlf=false https://github.com/MusicJapanLLC/music-japan-cloud-inference.git mj-public-dev
cd mj-public-dev
$run = 'runs/vda/' + (Get-Date -Format 'yyyyMMdd-HHmmss')
git switch -c $run
python live_dev_bridge.py --execute --public --client "$env:LOCALAPPDATA\MusicJapan\FrontierRuntime\frontier_client.py" --branch $run --attempts 2 --output "evidence/$($run.Replace('/','-'))"
```

出力の `receipt.json` が `PASS_VERIFIED` になった場合だけ `selected-edits.json` が今回の採用候補
修正対象の元ファイルや本番サービスは自動で上書きしない
実行前に別のファイルをステージングしている場合は拒否する

```powershell
python live_dev_bridge.py
python -m unittest discover -p 'test_*.py' -v
```

引数なしは通信・推論・クラウド起動のないドライラン
単体テストは制御処理の検証であり、139 個の開発課題をモデルが解いたという意味ではない

## 実行記録の読み方

`evidence/live-dev-20261018/` は、実際に取得したモデル出力を同一プロンプトで再生した初回の結合検証
実生成のクライアント処理は 158.704 秒、1,273 completion tokens、stop 終了だった
再生に要した時間を新たな生成速度として扱わない

`evidence/live-dev-fresh-20261018/` は、保存済みの回答を再生せず、基準テストの後に既存クライアントを直接呼んだ検証用の保存先
このフォルダの最終状態は、その中のレシートを正本とする

クラウドの入力と結果は `dev_requests/` と `dev_results/` に記録する
応答の request ID、入力ハッシュ、実行コミット、実行 ID が対応しなければ採用しない
SHA-256 はデータの整合性確認であり、秘密鍵署名や外部モデルの重み証明ではない

元のモデル回答は外側に Markdown の JSON フェンスがあった
そのため厳密な JSON 指示には不合格で、フェンスだけを除いたことを `outer_json_fence_only` として記録する
コードの手直しや JSON の内容修復は行っていない
公開用の生成レシートは最終回答・モデル申告・使用量などだけを残し、提供元の推論テキストは保存対象から外す

## テストと再確認の区別

サンプルは意図的に欠陥を入れた時間窓付きリトライ予算
4 つのテストが、容量・境界、無効な設定、時刻の逆行とリセット、24 スレッドの同時実行を確認する
修正前の失敗は別モデルとの比較結果ではない
同じ 4 テストの再実行は独立した新しい 4 課題として数えない
新しいコピー・新しいクラウド実行で再現を確認するもので、未知の業務課題に対する汎化性能試験ではない

## 修正した制御処理

テスト件数不明の基準実行から生成を始めない
失敗した候補コードを次のプロンプトにも含める
テストファイルを含む入力全体を結果にひも付ける
一度通った候補も新しい実行で再確認する
Docker のタイムアウト時は該当コンテナを片付ける
シンボリックリンクと特殊ファイルはワークスペースから排除する

クラウドのチェックは、ネットワークなし・読取専用・非 root・CPU/RAM/PID 制限付き Docker で行う
書き込み権限のある結果通知ジョブは別のマシンで実行し、候補コードを実行しない
これは隔離の実装であり、カーネル攻撃などを含む形式的な安全性証明ではない
